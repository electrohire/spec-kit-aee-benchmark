# The ratified default stack

This document is the defaults record of the Defaults Tournament (spec and execution record in the benchmarking goal's files, 2026-10-26): the combination the tournament ratified as the default stack, each component's disposition, and the evidence each disposition stands on. The gate decision was (c), the offline-only close — defaults set on replay evidence, behavior-affecting candidates unpromoted — taken under the pre-committed recommendation rule because exactly one clear champion distinct from the previous default emerged offline. The ratified state is held by frozen tests (tests/test_tournament_defaults.py, in the H-2 style): changing a default is a registration act, never a silent edit.

## The ratified combination

* State layer: the residual protocol ON, with per-phase re-anchoring in the workflow path and the C-4 abstain rule (the transform applies to the measured phase classes — specify, plan, tasks, solve — and every unmeasured class abstains until measured).
* Input hygiene: genesis preamble suppression ON at every segment genesis (the tournament's F1) — system messages in full, the problem statement verbatim, every other standing brief message as a digest reference line. The wiring default is on; a freeze config carrying `genesis_preamble_suppression: false` restores the unsuppressed genesis byte-for-byte.
* Budget layer: the amended cap split (quotas keyed by phase class and, for construction, by completion mode; the tasks class unpriced, the policy abstains) and the gate-loop budget at its ratified default, `gate_loop_budget_calls: 20`, carried explicitly by freezes.

## The priced pair (claim N-1, offline condition)

* On the identical frozen campaign corpus with the identical estimator, the previous default stack (the champion) replays at 3,298,151 sent tokens and the ratified stack at 3,047,322 — a margin of 250,829 sent tokens (7.6 percent), exact arithmetic over 16 admitted campaign attempts, zero digest-sync failures. The acceptance replay for this ratification, driving this repository's own session machinery with suppression on and off over the frozen corpus, reproduces both figures exactly; it is desktop evidence, cited in the tournament close-out report.
* N-1's live condition is untested: no live window was funded under gate decision (c), so the ratified stack's live margin over the champion is asserted on replay evidence only. The champion's pooled live record (367,891 per resolved task) stands as the live bar any future live window must beat at non-inferior deliveries.

## Dispositions

* Residual protocol (T-1): stays. Main effect −13,885,072 sent tokens across the factorial; negative in every pairing; digest sync held in every correctly constructed cell.
* Per-phase re-anchoring (T-2): stays. Main effect −2,446,868.5; its distinct remainder is the state-block reset at segment boundaries (plan −300,284, tasks −160,933 on the recorded corpus; specify and solve exactly zero, named under the abstain discipline).
* Genesis preamble suppression (T-3): stays, and its extension to every segment genesis is the ratified margin. Main effect −3,012,623. One premise correction travels with this ratification: the claim's 295-token bound is a workflow-genesis figure — workflow geneses suppress to at most 295 — while probe geneses suppress to at most 411, because the transform keeps system text in full and the probe genesis's system text is larger. Both figures are measured; the bound is recorded per path, not averaged.
* Cap split (T-4): stays. Against its off state (the pre-amendment single-draw rule) it frees the same 5,637,933 over the frozen draw record (151 draws, recomputed exactly by two independent appliers) but truncates zero observed successes where the single-draw rule truncates one — the off state is dominated on the (cost, function) pair, which is a positive contribution.
* Gate-loop budget (T-5): stays at 20, under the protective-mechanism carve-out. The raw kill rule removes it — its corpus main effect is exactly zero (no recorded attempt in the corpus reached a submission) — but the carve-out governs: the failure mode it bounds is real (the October attempt that motivated the mechanism, and the adversarial infinite-resubmission stream, which terminates on a budget of 6–8 where the key-absent control burns the full 41-call phase guard and never reaches plan), its unbounded cost is a whole phase, its carrying cost is one config key and measured corpus cost zero, and the bound is not duplicated by any other default mechanism.
* RTK (T-6): out — removed by the S-1 safety battery, not by the kill rule, and never promoted. In the tournament's specified application (filtering pre-recorded output before it enters context), RTK v1.1.0 lost 927 of 1,824 planted failure signals unrecoverably; its pipe mode stores no recall entries and its output carries no recovery pointer. A recorded qualification stands: RTK's live wrapper modes behaved correctly on a synthetic failing suite (failure line kept, exit codes propagated, recall byte-equal) — a different deployment shape a future registration could take up; it changes nothing here. RTK is not a default, is not vendored, and no fallback clause applies to it.
* Headroom (T-7): out — removed by the S-1 safety battery, never promoted. Headroom 0.41.0 lost 774 of 1,824 planted failure signals, including genuine failure lines from the corpus's own recorded outputs. Its byte-reduction figures from the same run are diagnostics, not a contribution, and are cited nowhere as one.
* Token-router (T-8): not promoted — stays opt-in, behind the E-1 verbatim-source fence (routed lines carry source locators, the raw output is digest-addressable, router output never enters evidence paths). It passed eligibility (E-1) and the safety battery (S-1: 1,824 of 1,824 planted signals and all 31 genuine failure lines survived), and its offline saving is an upper bound of 621,412 bytes over the distinct-output corpus — but 542 of 608 outputs returned empty selections under the registered failure-vocabulary policy, so live the model would re-read by locator and the realized saving would be far below the bound. Its live value is an open, priced question for a future envelope. One premise correction travels with this record: the token-router at its pinned version (v2.8.1) is not Ollama-backed — its changelog records the backend removed and its documentation states no model, login, or network by default; the 2026-09-22 evaluation's premise was stale, and eligibility was tested against the real pinned tool.
* The futility rule: excluded by evidence before the tournament (claim C-5: −5.2 points of function), named in the spec as a settled exclusion, and not a toggle in any cell.

## What this record does not establish

* It does not establish live savings for the ratified stack — gate decision (c) spent zero inference, and every figure above is replay evidence over this program's recorded corpus, as the tournament's own bounds state.
* It does not establish that a component removed here is useless everywhere — only that, in every combination the factorial priced on this corpus, it did not earn a place in this default stack. The evidence stays on the record; a future program with different traffic may re-open a component by registration, not by drift.
